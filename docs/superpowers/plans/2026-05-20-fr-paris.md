# Französische Version (/fr/) + Paris — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Eine französische Sprachversion unter `/fr/` mit programmatischen Paris-SEO-Seiten (20 Arrondissements × 10 Branchen) aufbauen, ohne die deutsche Live-Seite zu verändern.

**Architecture:** Manuelles `/fr/`-Spiegel-Verzeichnis. Neue FR-Daten-Dateien speisen FR-Page-Templates (Astro `getStaticPaths`). `BaseLayout` wird locale-fähig (Props mit DE-Defaults) und rendert hreflang. DE-Komponenten bleiben unberührt; einzige DE-Änderung: ein Sprachumschalter in `Navbar.astro`.

**Tech Stack:** Astro 4 (static), TypeScript, Tailwind, React-Islands. Verifikation über `npm run build` + Grep im `dist/`-Output (kein Unit-Test-Runner im Projekt vorhanden — das ist die projektgerechte Prüfmethode).

---

## Wichtige v1-Entscheidung: Lead-Formular auf FR-Seiten

Die DE-Nischen-Seiten erzeugen via `LeadForm`/`LeadFormDoener` → `public/api/submit.php` → Boomerang eine **sofortige Demo-Karte**. Für FR-Branchen existieren **keine Boomerang-Templates**.

**v1-Vorgehen (in diesem Plan umgesetzt):** FR-Nischen-Seiten bekommen **keinen Demo-Karten-Formular-Flow**, sondern einen **schlanken Lead-CTA** (WhatsApp + einfaches Kontaktformular ohne Demo-Karte). Der Demo-Karten-Flow für FR wird nachgezogen, sobald Boomerang-FR-Templates existieren (separater Plan).

> ⚠️ **Vor Task 7 vom User bestätigen lassen:** WhatsApp/Kontakt-CTA für v1 ok? Oder soll zuerst Boomerang-FR eingerichtet werden?
